## 新・うさこシューティング 技術・ゲーム仕様書  
## 1. プロジェクト概要  
**ゲームジャンル**  
2D横スクロールシューティング  
**技術**  
* Phaser  
* TypeScript  
* Webブラウザ  
**ゲームのコンセプト**  
**「撃って、避けて、しゃべる」**  
横スクロールシューティングをプレイしながら、キャラクター同士の会話やストーリーが展開されるゲームを目指す。  
ゲーム中に会話が発生する構成は『新・光神話 パルテナの鏡』を参考とする。  
ただし、ストーリーやキャラクター設定については後から決定するため、ゲームシステムとストーリー再生機能は分離して設計する。  
  
⸻  
  
## 2. 開発方針  
本プロジェクトでは、**最初から3人で同時にゲーム本体を開発するのではなく、フェーズ0でシューティングの基礎を一人で完成させる。**  
フェーズ0完了後、完成したシューティング基盤を土台として3人に分かれて開発する。  
これにより、  
* ゲーム本体の実装箇所によるコンフリクトを減らす  
* 3人が並行して開発できる状態を早期に作る  
* シューティングの基本仕様を共通化する  
* それぞれの担当領域を明確にする  
ことを目的とする。  
  
⸻  
  
## 3. 開発フェーズ  
## フェーズ0：シューティング基礎の完成  
**担当**  
**3人のうち1人が担当**  
**目的**  
まず、**「ゲーム開始からゲーム終了までプレイできる横スクロールシューティング」**を完成させる。  
この段階では、ストーリーや凝った演出、敵の種類などは最小限にする。  
**必須機能**  
* ゲーム開始  
* プレイヤー操作  
* プレイヤー移動  
* 通常弾の発射  
* 敵の出現  
* 敵の撃破  
* 敵弾  
* プレイヤーへのダメージ  
* プレイヤーHP  
* ゲームオーバー  
* 横スクロール  
* ステージ進行  
* ボス  
* ボス撃破  
* ステージクリア  
**完成条件**  
以下の一連の流れが成立すること。  
```
ゲーム開始
↓
プレイヤー操作
↓
敵出現
↓
敵を撃つ・避ける
↓
ステージ進行
↓
ボス出現
↓
ボス戦
↓
ボス撃破
↓
ステージクリア

```
このフェーズでは、画像・音声・敵・背景などは仮素材でもよい。  
  
⸻  
  
## 4. フェーズ1：3人による並行開発  
フェーズ0が完成した後、以下の3担当に分かれる。  
```
                    フェーズ0
                       │
             シューティング基礎完成
                       │
          ┌────────────┼────────────┐
          ↓            ↓            ↓
       A：ゲーム内容  B：演出・物語  C：基盤・ロード

```
  
⸻  
  
## 5. A担当：敵・ステージ・ゲーム内容  
## 役割  
ゲームそのものの**「遊び」を増やしていく担当**。  
**主な担当**  
* 敵の追加  
* 敵AI  
* 敵の攻撃パターン  
* ボスの追加・強化  
* ステージ追加  
* ステージギミック  
* 敵の出現パターン  
* アイテム  
* 武器  
* ステージイベント  
* 難易度調整  
**敵**  
基本的なEnemyを拡張し、  
```
BasicEnemy
FastEnemy
TankEnemy
SniperEnemy
LaserEnemy
ShieldEnemy
...

```
などを追加できる構造にする。  
敵生成はFactoryを介して行う。  
```
EnemyFactory.create("basic")
EnemyFactory.create("fast")
EnemyFactory.create("tank")

```
これにより、敵を追加しても既存のゲーム基盤への影響を最小限にする。  
**ステージ**  
ステージ内容は可能な限りデータとして管理する。  
```
data/
└── stages/
    ├── stage01.json
    ├── stage02.json
    └── stage03.json

```
例えば、  
```
{
  "id": "stage01",
  "events": [
    {
      "time": 1000,
      "type": "spawn_enemy",
      "enemy": "basic",
      "count": 3
    },
    {
      "time": 5000,
      "type": "spawn_enemy",
      "enemy": "fast",
      "count": 2
    }
  ]
}

```
のように、ステージの内容をデータとして定義する。  
  
⸻  
  
## 6. B担当：演出・ストーリー再生  
## 役割  
「撃って、避ける」だけではなく、**「しゃべる」部分を担当する。**  
**主な担当**  
* 会話システム  
* ストーリー再生  
* 会話ウィンドウ  
* キャラクター名表示  
* キャラクター立ち絵  
* 会話送り  
* 会話中のゲーム処理  
* ステージ中のイベント演出  
* 画面エフェクト  
* カメラ演出  
* ボス登場演出  
* その他ゲーム演出  
**DialogueManager**  
会話機能はシューティング本体から分離する。  
```
DialogueManager
├── start()
├── next()
├── show()
├── hide()
└── end()

```
会話内容もデータとして管理する。  
```
data/
└── dialogues/
    ├── stage01.json
    ├── stage02.json
    └── boss01.json

```
例：  
```
{
  "id": "stage01_intro",
  "messages": [
    {
      "character": "usako",
      "text": "敵が来たよ！"
    },
    {
      "character": "friend",
      "text": "任せて！"
    }
  ]
}

```
**重要な仕様**  
会話中も基本的には**シューティングゲームが継続する**。  
```
敵が出現
↓
プレイヤーが戦闘
↓
会話開始
↓
会話しながら戦闘
↓
会話終了
↓
通常戦闘

```
これを本ゲームの特徴とする。  
  
⸻  
  
## 7. C担当：ロード・基盤・技術的最適化  
## 役割  
ゲームの裏側を担当し、**3人が開発しやすい環境を整える。**  
単純なロード処理だけではなく、共通システム・パフォーマンス・アセット管理なども担当する。  
**主な担当**  
* AssetManager  
* アセットロード  
* アセットアンロード  
* ステージ切り替え  
* Object Pool  
* 共通イベント基盤  
* 共通ゲーム状態管理  
* パフォーマンス改善  
* メモリ管理  
* 画像最適化  
* 音声ロード最適化  
* 共通ユーティリティ  
* 必要に応じた共通UI基盤  
  
⸻  
  
## 8. AssetManager  
ステージごとに必要な画像・音声などを管理する。  
```
AssetManager.loadStage("stage01")
AssetManager.unloadStage("stage01")

```
例えば、  
```
Stage01開始
↓
Stage01の画像・BGM・SEなどをロード
↓
ゲームプレイ
↓
Stage01終了
↓
不要なアセットを解放

```
とする。  
これにより、画像や音声が増えてもゲーム全体のメモリ使用量が増え続けることを防ぐ。  
  
⸻  
  
## 9. Object Pool  
弾・敵・エフェクトなど、頻繁に生成・削除されるオブジェクトはPoolで管理する。  
```
弾を発射
↓
Poolから取得
↓
使用
↓
画面外・命中
↓
Poolへ返却

```
毎回、  
```
new Bullet()
destroy()
new Bullet()
destroy()

```
を繰り返すのではなく、既存オブジェクトを再利用する。  
  
⸻  
  
## 10. イベント基盤  
ステージ上の出来事は、可能な限りイベントとして扱う。  
```
EventManager

```
によって、  
```
敵出現
会話開始
BGM変更
SE再生
画面揺れ
ボス登場
背景変更
アイテム出現

```
などを発生させられるようにする。  
将来的には、  
```
{
  "time": 30000,
  "type": "dialogue",
  "id": "boss_warning"
}

```
のようなデータだけでゲームイベントを組み立てられる状態を目指す。  
  
⸻  
  
## 11. 3人の担当境界  
3人が同じファイルを頻繁に編集しないよう、担当を明確にする。  

| 領域              | 主担当          |
| --------------- | ------------ |
| Player          | フェーズ0担当 / 基盤 |
| Bullet          | フェーズ0担当 / 基盤 |
| Collision       | フェーズ0担当 / 基盤 |
| Enemy           | A            |
| Boss            | A            |
| EnemyFactory    | A            |
| StageManager    | A            |
| Stageデータ        | A            |
| DialogueManager | B            |
| Dialogue UI     | B            |
| Storyデータ        | B            |
| 演出              | B            |
| AssetManager    | C            |
| ObjectPool      | C            |
| EventManager    | C            |
| Loading         | C            |
| 共通基盤            | C            |
  
フェーズ0で作成したシューティング基盤は、フェーズ1以降できるだけ安定したインターフェースとして扱う。  
  
⸻  
  
## 12. 拡張性の設計方針  
このゲームでは、今後、  
* ステージ追加  
* 敵追加  
* ボス追加  
* 武器追加  
* 会話追加  
* BGM追加  
* SE追加  
* ボイス追加  
* 演出追加  
が発生することを前提とする。  
そのため、  
**「コードを大きく書き換えてコンテンツを追加する」のではなく、「データや新しいクラスを追加して拡張する」**  
ことを基本方針とする。  
  
⸻

## 開発の最終目標  
まずフェーズ0で、  
**「ちゃんと遊べるシューティング」**  
を完成させる。  
その後3人で、  
**Aが「ゲームを面白くする」Bが「ゲームを物語として魅せる」Cが「ゲームを技術的に支える」**  
という形で開発を並行化する。  
最終的には、  
**「撃って、避けて、しゃべる」**  
という本作独自の体験を、拡張しやすいゲーム基盤の上で実現する。
